# positum.ee — рабочий процесс

## Две среды

| | prod | dev |
|---|---|---|
| Адрес | https://positum.ee | https://dev.positum.ee (basic-auth) |
| Папка | `~/domeenid/www.positum.ee/htdocs` | `~/domeenid/www.positum.ee/dev` |
| База | `d123384sd516698` | `d123384_dev` |
| Почта | уходит клиентам | заблокирована |
| Платежи | боевые | шлюзы отключены |
| Индексация | да | `noindex` + basic-auth |

Изоляцию dev обеспечивает `wp-content/mu-plugins/00-dev-guard.php`.
Он существует только на dev и намеренно **не** версионируется в git.

## Что лежит в этом репозитории

Только то, что пишется руками:

- `wp-content/themes/wportfolio/` — активная тема
- `wp-content/mu-plugins/positum-*.php` — свои mu-плагины
- `scripts/` — скрипты синхронизации и выкатки
- `scripts/plugins.txt` — эталонный снимок версий ядра и плагинов

Ядро WordPress, плагины и загрузки в git **не** попадают: они ставятся
через WP-CLI и весят 1.5 GB. Правило задано в `.gitignore` от обратного —
игнорируется всё, кроме явно перечисленного.

## Доступ к dev

`https://dev.positum.ee` закрыт HTTP-авторизацией: пользователь `dev`.
Пароль хранится в `~/domeenid/www.positum.ee/dev/.htpasswd` (в git не попадает).
Сменить пароль:

```bash
htpasswd -c ~/domeenid/www.positum.ee/dev/.htpasswd dev
# если htpasswd недоступен:
echo "dev:$(openssl passwd -apr1 'НОВЫЙ_ПАРОЛЬ')" > ~/domeenid/www.positum.ee/dev/.htpasswd
```

Логин администратора WordPress на dev — тот же, что на prod: база скопирована целиком.

## Цикл работы

```
   локальный клон  <--- git pull ---  GitHub  --- git pull --->  dev
   (правим код)     --- git push --->        <--- git push ---
                                                |
                                     проверяем на dev.positum.ee
                                                |
                                    scripts/deploy-to-prod.sh
                                                |
                                              prod
```

Править код можно из двух мест — но не из обоих одновременно, иначе разъедутся.

**Вариант А, локально** (эта папка на компьютере):

1. правим код, `git add … && git commit && git push`
2. `./scripts/pull-to-dev.sh` — подтягивает коммит на dev и сбрасывает кэш
3. проверяем на https://dev.positum.ee/

**Вариант Б, прямо на сервере** (VS Code Remote SSH в `~/domeenid/www.positum.ee/dev`):

1. правим код, сразу видим результат на https://dev.positum.ee/
2. `git add … && git commit && git push`
3. локально не забыть `git pull`

**Выкатка на prod — общая для обоих вариантов:**

```bash
ssh virt122995@positum.ee
~/domeenid/www.positum.ee/dev/scripts/deploy-to-prod.sh
```

Скрипт снимает бэкап базы и кода, делает `git merge --ff-only` и сбрасывает кэш.
`--ff-only` намеренно: если на prod кто-то правил файлы руками, выкатка
остановится с ошибкой, а не затрёт эти правки молча.

Чтобы подтянуть в dev свежие данные с боевого сайта:
`./scripts/sync-prod-to-dev.sh` (загрузки + база + повторная изоляция).

Скрипты лежат только в dev и в локальном клоне. На prod они намеренно
не выкачиваются (`git sparse-checkout`), чтобы не светить в веб-корне пути
и имена баз.

## Важное ограничение: содержимое базы не выкатывается

Макеты Elementor, настройки JetEngine, товары и страницы хранятся **в базе**,
а не в файлах. Залить базу из dev в prod нельзя — это затрёт заказы,
клиентов и всё, что накопилось на боевом сайте с момента копирования.

Поэтому такие изменения переносятся точечно:

- **Шаблоны Elementor** — «Шаблоны → Сохранённые шаблоны → Экспорт»,
  затем импорт на prod.
- **Мета-поля и типы записей JetEngine** — экспорт/импорт в интерфейсе JetEngine.
- **Настройки плагинов** — повторить руками на prod.
- **Правки страниц** — повторить руками на prod.

Dev нужен, чтобы проверить, что изменение работает и ничего не ломает.
Перенос на prod для содержимого базы — ручной и осознанный.

## Обновление плагинов и ядра

Автообновления на dev отключены. Порядок такой:

1. `./scripts/sync-prod-to-dev.sh` — dev становится точной копией prod
2. обновляем на dev, проверяем магазин: каталог, корзину, кассу
3. если всё хорошо — обновляем на prod
4. `./scripts/plugins-snapshot.sh` — фиксируем новые версии в git

## Бэкапы

Лежат в `~/backups/`. Создаются автоматически перед каждой выкаткой
и перед каждой синхронизацией. Периодически чистить — место не бесконечное.
